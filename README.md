# Проектирование высоконагруженного сервиса совместной работы с документами

Курсовая работа по дисциплине «Проектирование высоконагруженных систем».

## 1. Тема и целевая аудитория

### Тип сервиса

Сервис для создания, хранения и совместного редактирования документов (аналог Notion).

### Целевая аудитория

В качестве основного рыночного ориентира для проектируемого сервиса рассматривается **Notion**. Сервис используется как частными пользователями, в том числе студентами и молодыми специалистами, так и рабочими командами и компаниями. Проектируемая система ориентирована преимущественно на пользователей в возрасте **18–34 лет** [[5]](#source5), а также на рабочие команды численностью до 200 участников.

В августе 2024 года Notion преодолел отметку в **100 млн пользователей** [[1]](#source1). При этом компания публично не раскрывает значения MAU и DAU для всей платформы, поэтому при проектировании нагрузки используются собственные расчётные показатели.

Внешние оценки подтверждают значительную активную аудиторию сервиса. По данным AICPB, мобильное приложение Notion в июне 2026 года имело около **8,2 млн MAU** [[4]](#source4). Кроме мобильных приложений, значительная часть пользователей работает с Notion через веб- и desktop-клиенты, поэтому суммарная активная аудитория сервиса существенно выше мобильного MAU.

Для дальнейшего проектирования высоконагруженной системы принимаются следующие целевые показатели:

| Метрика                         | Значение |
| ------------------------------- | -------: |
| Зарегистрированные пользователи | 100+ млн |
| Месячная аудитория (MAU)        |   20 млн |
| Дневная аудитория (DAU)         |    5 млн |
| DAU / MAU                       |      25% |

Значения **MAU = 20 млн** и **DAU = 5 млн** являются проектным допущением и используются для последующего расчёта RPS, объёма хранилища, сетевого трафика и требований к масштабированию. Они не являются официальными метриками Notion.


#### География аудитории

Notion изначально имеет международную аудиторию. Ещё в 2021 году компания сообщала, что **более 80% пользователей находились за пределами США**, а сервис использовался пользователями как минимум из 28 стран [[6]](#source6). В настоящее время Notion указывает присутствие более чем в 50 странах [[2]](#source2).

По оценке Similarweb для `notion.com` за август 2026 года, крупнейшие источники веб-трафика распределялись следующим образом [[5]](#source5):

| Страна        | Доля веб-трафика |
| ------------- | ---------------: |
| США           |           17,27% |
| Южная Корея   |           11,87% |
| Япония        |            9,73% |
| Бразилия      |            4,28% |
| Индия         |            4,22% |
| Другие страны |           52,63% |

Таким образом, проектируемый сервис должен рассматриваться как **глобальная система**, аудитория которой распределена между Северной Америкой, Европой, Азией и другими регионами. Это необходимо учитывать при дальнейшем проектировании географического размещения инфраструктуры, CDN, файлового хранилища и механизмов репликации данных.


### Функционал MVP

1. **Регистрация и авторизация.** Регистрация по электронной почте, вход по паролю или OAuth, завершение активных сессий и восстановление доступа.
2. **Рабочие пространства.** Создание рабочего пространства, приглашение и удаление участников, роли `owner`, `editor` и `viewer`.
3. **Работа с документами.** Создание и удаление документов, вложенная иерархия страниц, добавление, изменение, удаление и перемещение блоков.
4. **Совместное редактирование.** Одновременная работа нескольких пользователей на одной странице, отображение присутствующих участников, отображение изменений в реальном времени.
5. **Поиск.** Полнотекстовый поиск по названию и содержимому доступных пользователю документов внутри выбранного рабочего пространства.
6. **Файлы и изображения.** Загрузка, скачивание и отображение вложений внутри документа; права на файл наследуются от страницы.

### Ключевые продуктовые решения

1. Документ состоит из упорядоченных блоков. Каждый блок можно изменять и перемещать независимо от остальных.
2. Рабочее пространство является основной единицей изоляции данных и прав доступа.
3. Изменения документа должны быть видны другим редакторам почти в реальном времени; для поиска допускается небольшая задержка обновления индекса.
4. Пользовательские файлы не сохраняются непосредственно в основной реляционной базе данных.
